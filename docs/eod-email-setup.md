# End-of-Day email — setup (Power Automate)

When **End Day** is pressed, the app writes one row to a new **EndOfDayLog**
list. That row already contains a **fully built HTML email body** with the same
insights as the on-screen End-of-Day dashboard (total rotations, units, goals
met, skipped/overridden, manual, open time, and the per-commodity and
per-section breakdowns). A Power Automate flow watches the list and sends it —
**no tokens or expressions to map**, it just drops one field into the email
body. This is the simplest of the three notification flows.

## 1. One-time SharePoint change — create the `EndOfDayLog` list

Create a list named exactly **`EndOfDayLog`** on the Outlet Rotation App site
with these columns (names must match — the app writes them):

| Column | Type |
|---|---|
| `Title` | Single line of text (default — leave it) |
| `OutletName` | Single line of text |
| `DateLabel` | Single line of text |
| `Subject` | Single line of text |
| `TotalRotations` | Number |
| `TotalUnits` | Number |
| `GoalsMet` | Number |
| `GoalsTotal` | Number |
| `Skipped` | Number |
| `ManualRotations` | Number |
| `EndedByEmail` | Single line of text |
| `EndedAt` | Date and Time |
| `EmailBodyHtml` | **Multiple lines of text — Plain text** (NOT rich/enhanced) |

> `EmailBodyHtml` must be **plain** multi-line text, not "Enhanced rich text".
> Rich text re-encodes the HTML and breaks the layout.

Until this list exists, End Day still works (and the on-screen summary still
shows) — it just can't send the email.

The numeric columns (`TotalRotations`, `TotalUnits`, `Skipped`, …) are also handy
for Power BI / reporting later; the email itself only needs `Subject` and
`EmailBodyHtml`.

## 2. Build the flow (Power Automate)

Create an **Automated cloud flow**:

1. **Trigger:** SharePoint → **When an item is created**.
   - Site Address: the Outlet Rotation App site.
   - List Name: **EndOfDayLog**.
2. Add **Office 365 Outlook → Send an email (V2)**:
   - **To:** `SAdhikari@goodwillcfl.org` (change/add recipients here anytime).
   - **Subject:** dynamic content **Subject**.
   - **Body:** click the **`</>` code view** button on the body box, then insert
     the dynamic content **EmailBodyHtml** as the entire body. (Code view makes
     the Send Email step treat it as HTML.)
3. **Save** and test by pressing **End Day** on an outlet with an open day.

That's it — one trigger, one action, two fields. Every End Day now emails a
complete record of the day.

## Notes
- The email content is generated by the app (`buildEndOfDayEmailHtml` in
  `lib/graph/day-summary.ts`), so it always matches the on-screen End-of-Day
  dashboard exactly.
- "Skipped / Overridden" is a single number — in this app an override *is* a
  skip (the section was intentionally passed over), so they are the same event.
- One End Day = one EndOfDayLog row = one email.
